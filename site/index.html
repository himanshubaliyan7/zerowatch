01 · The switchNo code changes

Change one endpoint

Your SDK calls, scripts and EMF log lines keep working. Point the endpoint at ZeroWatch and the data lands in your own account instead of a per-metric bill.

Today, on CloudWatch 
aws cloudwatch put-metric-data \
  --region us-east-1 \
  --namespace Shop --metric-name Orders \
  --value 1 --unit Count
With ZeroWatch 
aws cloudwatch put-metric-data \
  --endpoint-url http://zerowatch:8080/cloudwatch \
  --namespace Shop --metric-name Orders \
  --value 1 --unit Count

02 · How it worksYour cloud, your data

Detail stays on the node. The rest stays in your account.

The agent keeps per-second data where it was measured and sends compact summaries, logs and traces to a ZeroWatch server you run. Zoom into one host and the query goes to that host for the full detail.

On every node

Agent

  • Finds processes, ports, containers and log files
  • eBPF request, error and latency metrics, HTTPS included
  • Host CPU, memory, disk and network
  • Per-second store with anomaly scoring
In your AWS account

ZeroWatch server

  • CloudWatch API, OTLP, Prometheus remote write, StatsD
  • Metrics, logs and traces with S3 tiering
  • Clusters with replication and failover
  • Managed cloud and bring-your-own-cloud editions
For your team

Answers

  • Dashboards built for each service it finds
  • Alarms to Slack, PagerDuty, SNS or webhooks, including forecast alarms
  • Grafana through a Prometheus-compatible API
  • AI investigation and an MCP server

08 · Questions
Is it really open source?

Yes. The code is on GitHub under Apache-2.0, and you can run the whole thing on your own servers for free. Paid editions will add a managed service, bring-your-own-cloud operation and enterprise features on top.

Does it replace CloudWatch completely?

Not yet. Metric writes and reads (PutMetricData, GetMetricData, ListMetrics) and log writes (PutLogEvents) work today. Log reads, the alarms API and Logs Insights queries are in development. The status list above is kept current.

Where does my data live?

On servers you control. Self-hosted, everything stays on your machines. With the planned BYOC edition, data stays in your AWS account and only the control plane runs on ours.

Do I have to change my code?

No. eBPF picks up request, error and latency metrics from your services without instrumentation, and CloudWatch, OpenTelemetry, Prometheus and StatsD clients only need a new endpoint.

What does it run on?

Linux hosts and Kubernetes today, from one Go binary or a Helm chart. eBPF needs a modern kernel and root or the BPF capabilities. Windows and macOS agents are planned.
